Why this walkthrough begins with data

Motion sequences can reveal health and behavioural information. Before discussing deep learning, a reviewer needs to know how trajectories were captured, what every axis and target means, which participants consented, and whether each participant is isolated to one evaluation split. Those facts are absent from the archived notebooks.

Scope: this is not a diagnostic, rehabilitation prescription, fall-risk score, or identity system. It is preserved exploratory work awaiting a reproducible research protocol.

Architecture and information flow

consented sensor / motion-capture trials │ ▼ metadata + data dictionary ──► quality checks / coordinate validation │ │ ▼ ▼ participant-and-trial group split ──► training-only scaling + windows │ ┌─────────────────┴─────────────────┐ ▼ ▼ fixed-feature DNN ordered-window LSTM └─────────────────┬─────────────────┘ ▼ untouched participant-level test evaluation

A DNN is a plausible baseline when each row is a fixed engineered feature vector. An LSTM becomes plausible only when window order, sampling rate, units, and target horizon are defined. Architecture choice cannot compensate for unknown labels or leakage.

The critical leakage boundary

Do not split raw rows or overlapping windows randomly. Adjacent frames from one walk are highly similar; putting them in train and test would make the model appear to generalise when it has merely seen the same person and trial.

participant P17 / trial T04 → frames 1…500 → windows 1…N → assigned to TEST participant P17 / trial T05 → frames 1…500 → windows 1…N → assigned to TEST participant P22 / trial T01 → frames 1…500 → windows 1…N → assigned to TRAIN Split participants/trials first. Window and normalise separately within each split.

Recovery checklist

1. Restore provenance
Secure the original CSVs, consent/reuse conditions, device details, and a data dictionary.
2. Define the target
State whether the model predicts coordinates, an event, or a score, with units and horizon.
3. Freeze the manifest
Use participant and trial IDs to create train/validation/test splits before feature work.
4. Earn a result
Compare with simple baselines and report held-out errors, uncertainty, and failure modes.
