01 · Conclusion first

A runnable metadata baseline, not a personalised service.

The original app depended on missing model files and a hard-coded API key. The repaired version builds its own sparse vector index from a committed CSV, selects films by a validated TMDB ID, and can render recommendations without any network request.

03 · Data integrity boundary

The unsafe title merge is visible and contained.

The legacy notebook joins TMDB Movies and Credits on title. Three titles repeat, allowing text metadata from one film to be combined with credits from another. The runnable CSV excludes every row with one of those repeated titles instead of presenting falsely precise suggestions.

Legacy artifactObserved issueCurrent handling
4,806-row pickle12 rows have repeated-title ambiguityUse a 4,794-row unambiguous CSV

A proper future data refresh joins raw tables on the TMDB numeric identifier, logs the source version and licence boundary, reruns validation, and only then reconsiders the excluded titles.

04 · Model boundary

What the representation learns—and what it cannot.

It uses

  • Overview, genres, keywords, up to three cast names, and directors.
  • English stop-word removal and up to 5,000 count features.
  • Cosine similarity to rank metadata-nearest rows.

It does not use

  • User identities, histories, ratings, clicks, or feedback.
  • Streaming availability, recency, popularity, or editorial curation.
  • Semantic embeddings, diversity constraints, or fairness evaluation.

The original notebook is retained for provenance, but cannot be rerun from this repository alone because its raw TMDB input files are absent.

06 · Responsible next step

Measure relevance before calling it a recommender evaluation.

To compare recommenders responsibly, first obtain permitted raw source data and correct the join. Then collect offline relevance judgments or consented, anonymised interactions. Only then compare this baseline with TF-IDF or embedding retrieval using the same held-out judgments, reporting Precision@K, recall, catalogue coverage, diversity, and failure slices.

Until then, this remains an inspectable learning project: a working content-similarity interface with clearly bounded claims.
