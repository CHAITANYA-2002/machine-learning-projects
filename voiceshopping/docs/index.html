Machine-learning portfolio / speech + LLM + web automation

Voice-guided grocery cart prototype

A safety-aware walkthrough of a desktop proof of concept that turns speech into validated cart proposals and browser-assisted shopping—not autonomous purchasing.

Partially runnable · live account automation not verified

Primary design decision: no autonomous checkout

Speech is noisy, LLM output is probabilistic, retailer pages change, and purchases are consequential. The correct boundary is an assistant that can propose and add explicitly confirmed items, then hands control back to the user for final cart, delivery, price, substitution, and payment decisions.

Hard stop: do not bypass MFA, captchas, retailer safeguards, or the user’s final review. A voice command is not approval for a financial transaction.

End-to-end data flow

microphone → speech recognition → transcript → OpenAI proposal │ ▼ JSON parse + schema/length/bounds checks │ ▼ explicit user read-back and confirmation │ ▼ Selenium cart operation → visible cart review │ ▼ manual retailer checkout / payment

Secrets come from environment variables only. The `.env.example` file names every required value without exposing a value; `.env` and browser logs remain ignored.

Untrusted-model boundary

InputRiskControl added
LLM JSONMalformed, nested, overly long, or unexpected dataOnly a dictionary with bounded text is accepted.
QuantityFractional, boolean, negative, or excessive amountOnly an integer 1–100 is accepted.
Speech transcriptMisrecognition and ambiguityUser must hear/see and confirm proposed cart lines.
Retailer pageSelector drift, substitutions, prices, MFA/captchaVisible review and manual final checkout.

The validation module does not make an LLM safe. It narrows the data shape before browser automation and ensures invalid proposals fail closed.

Threat model

Secrets
Keys and passwords must stay out of source, logs, screenshots, and chat transcripts.
Unwanted purchase
Require separate confirmation for cart changes; never automate payment.
Data disclosure
Voice transcripts may reveal preferences, addresses, or health-related items; retain minimally.
Site drift
Fail safely when selectors or retailer flows change; do not attempt bypasses.

What was verified

tests/test_order_validation.py ├─ valid item text is normalised ├─ invalid payload structures are rejected ├─ malformed details are rejected ├─ valid quantities are accepted └─ boolean, fractional, negative, zero, text, and >100 quantities fail Result: 13 tests passed Syntax: four Python entry points compiled successfully

These checks intentionally avoid calling OpenAI, opening a microphone, logging into any site, or controlling a browser. They establish a deterministic local boundary only.

Execution checklist for an authorised local demo

  1. Create a virtual environment and install the pinned requirements.
  2. Copy `.env.example` to ignored `.env`; use only the user’s own secrets.
  3. Leave store automation disabled until selectors and retailer terms are reviewed.
  4. Run the test suite first.
  5. Use a visible browser and inspect the cart before each action.
  6. Stop at retailer checkout; the user completes payment manually.

Current conclusion

This is a useful prototype for integrating voice I/O, structured LLM extraction, and browser automation. It is not ready to act independently on a consumer account. The next professional step is a reviewed UI with per-action approval, cart-diff checks, redacted audit logs, mocked external integration tests, and accessibility/consent review.
