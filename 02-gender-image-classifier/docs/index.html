A transparent recovery assessment of a binary CNN notebook. This document separates what the code contains from what can actually be claimed without the original images, consent records, and held-out evaluation.

Recovery required · no model result claimed

The central constraint

The original folder name says “Man/Woman,” but appearance does not establish gender identity. The notebook is only a historical binary image-classification exercise over unspecified dataset labels. It is not appropriate for profiling, surveillance, hiring, admissions, access control, or decisions about people.

Why this changes the engineering: a high score can be produced by hairstyles, photography source, image compression, background, or repeated people—not a valid or ethical understanding of gender.

What the notebook actually does

directory images │ ├─ ImageDataGenerator: rescale, flip, shift, shear, rotate, zoom ▼ flow_from_directory(150×150 RGB, batch=32, binary labels) ▼ Conv32 → Pool → Conv64 → Pool → Conv128 → Pool → Conv128 → Pool ▼ Flatten → Dropout(.5) → Dense512/ReLU → Dense1/Sigmoid ▼ Adam + binary cross-entropy → 25 epochs, fixed 100 steps/epoch

Augmentation is training-only image perturbation. It cannot add consent, provenance, demographic coverage, or a credible evaluation boundary. The notebook trains on one iterator and then predicts from that same iterator; it has no valid test-set measurement.

The missing boundary

Before a scientific rerun, images must be deduplicated and split by person, source, and photo session. Randomly splitting files can put nearly identical images—or the same person—on both sides of the evaluation boundary.

consented images + dataset card → join person/source metadata → group-aware train / validation / test manifest → fit augmentation + CNN on training only → tune on validation only → freeze configuration → evaluate once on untouched test set → publish uncertainty, failures, and prohibited uses

Recovery checklist

1. Establish rights
Record explicit consent, licence, retention, deletion, and access rules for every image.
2. Define labels
Document exactly what each folder label represents; never equate it with gender identity.
3. Build the manifest
Store image, label, person ID, source ID, session, and split in a reproducible CSV.
4. Measure honestly
Report per-label precision/recall/F1, confusion matrix, calibration, counts, and error cases—not only accuracy.

Current conclusion

The preserved notebook is useful as a record of an early CNN pipeline. It is not evidence of a dependable classifier. The appropriate next deliverable is a consented, well-documented research dataset and a leakage-safe evaluation protocol; until then, no trained artifact or interactive prediction surface should be published.
