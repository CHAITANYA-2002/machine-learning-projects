1 · Enhancement is not recovery

Super-resolution synthesises plausible high-frequency detail conditioned on learned image patterns. It does not recover pixels that the source did not contain.

Low-resolution image → learned RRDB prior → plausible ×4 image ≠ recovered source evidence
Never use generated detail as forensic, medical, legal, identity, or safety-critical evidence.

3 · Inference path

LR/*.jpg → BGR OpenCV read → RGB tensor [0,1] → RRDBNet checkpoint → clamp [0,1] → results/*_rlt.png

The network begins with a convolution, passes through 23 RRDB blocks, adds trunk residual features, then upsamples twice by two. The weight file is load-bearing: the architecture alone contains random parameters and cannot enhance an image meaningfully.

4 · The missing weight boundary

models/RRDB_ESRGAN_x4.pth

That required checkpoint is not in this repository. Therefore no local enhancement output, quality metric, or visual claim is reported. The upstream paper's benchmark scores belong to its own evaluation environment, not this checkout.

Quantitative quality is also unavailable. There is no controlled low-resolution/high-resolution benchmark pair for PSNR, SSIM, LPIPS, or perceptual-quality measurement.

5 · Original operational risks

The source script assumes CUDA, an architecture-compatible checkpoint, an input folder, and a writable output folder. It has no preflight report, so a missing asset becomes a low-level exception. The next implementation step is a CLI with argument-driven paths, CPU/GPU choice, and validation before inference.

Original architecture, utilities, images, and upstream documentation have been retained rather than deleted.

6 · Responsible use and state

  • Keep the original image and record model/version/settings beside every output.
  • Image rights, privacy, consent, and confidentiality remain unchanged by enhancement.
  • Do not upload protected imagery to third-party services without authority.
